[Repair_DVO_PO_0002601_11688BOX.sql](Repair_DVO_PO_0002601_11688BOX.sql) defaults
to read-only review. It validates the PO, both lines, reviewed row versions, stock
balance, audit history, pending document and seven trigger definitions.
An existing movement or changed evidence blocks the operation.

An approved commit adds 20 to Item.Quantity and records the actual posting time.
It inserts one native InventoryTransferLog row for PO 27784, entry 97646,
store 4001, batch 2511 and receipt unit cost 5.2836. Cashier ID 0 represents
the system correction. The normal triggers produce the stock audit, transfer
audit and one RMSTMP_InventoryMovement row. Both audit entries describe the
same stock change. The script verifies these records together before committing.

For future live execution, use a dedicated SSMS session during a maintenance
window. Confirm the physical boxes and reconcile integration document 7166
with the downstream system before posting. Pause receiving and the relevant
integration workers during the window. A synchronized document, existing movement
or other drift requires a fresh review. Keep the guards in place.

Run the entire file with @Commit = 0 to review. For a separately authorized
commit, use a fresh, uniquely named copy-only full backup from that day, with
checksums. Supply its server-side path as @BackupPath and set @Commit = 1.
The script checks backup history and runs RESTORE VERIFYONLY WITH CHECKSUM.
Use the COMMITTED result and InventoryTransferLogID to verify the posted movement.
This is a standalone repair script.

The [LocalDB test](../Tests/DVO_PO_0002601_LocalDB_Test.ps1) passed 31 checks
with synthetic rows, the seven captured Davao trigger definitions and
compatibility level 100. It tested backup and target guards, rollback after
forced failures, preservation of the original PO, repacking and sibling rows,
and duplicate rejection. It verified the new integration queue row. Downstream
processing and native RMS receiving were outside the fixture test.
