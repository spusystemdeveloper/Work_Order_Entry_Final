# Work Order Entry V8

VB.NET RMS add-ins for Work Order Entry and Order Processing Queueing.

## Database deployment

The application-referenced database objects are stored as individual,
idempotent SQL files with separate DVO and GSC definitions where the live
branches differ:

- `Database Components/Deployment/README.md` - deployment workflow and known
  blockers.
- `Database Components/Deployment/Manifest.csv` - all 49 audited objects,
  types, requirements, hashes, and placement.
- `Database Components/Deployment/Comparison/OBJECT_DIFFERENCES.md` -
  branch comparison.
- `Database Components/Deployment/Deploy_DVO_STORE_DB.sql` and
  `Deploy_GSC_STORE_DB.sql` - guarded SQLCMD drivers.
- `Database Components/Deployment/Objects/PortableBaseline` - seven required
  local-database definitions for GSC and future RMS branches that do not
  already have approved branch-specific versions.
- `Database Components/Migrations/Upgrade_GSC_STORE_DB_For_WorkOrderEntry.sql` -
  standalone, idempotent SQL migration script ready to execute in SSMS against
  `GSC_STORE_DB`.

The package was generated by read-only inspection. It does not modify either
live database. Always test the matching branch driver against a disposable
database restore before production deployment.

## Branch database lock

Branch selection is disabled by default. Configure it in the
password-protected **Settings** form under **Branch Functions**:

- Clear **Allow Branch Selection** and enter the **Assigned Database**
  (for example `DVO_STORE_DB` or `GSC_STORE_DB`) to lock the installation.
- Select **Allow Branch Selection** to show the store database selector
  during startup.
- Click **Save**, close the application, and start it again.

In locked mode, the application uses the local RMS Store Operations registry
connection and stops before login if its database does not match the assigned
database. The controls save `BranchSelectionEnabled` and
`ExpectedDatabaseName` in the deployed application configuration.

## Order tools

Work Order Entry now includes an order history window, a ready-for-invoicing
notification, and protection against saving or cancelling a stale recalled order.
Warehouse shortage alerts also appear automatically in the status bar; click
the alert or **Order actions → Warehouse shortages...** to open an affected order.
The list supports local search, picker selection, new/changed and zero-found
filters, result counts, and Clear filters without extra database queries.
Cashiers can accept a positive warehouse shortage after customer agreement;
saving reduces the quantity, amounts, and reserved stock together, preserves the
picker, and records the decision. RMS stock on hand is unchanged.
Open history or reload an order from **Order actions** in the bottom status bar.
History and shortage acceptance require the optional `Enable_WorkOrder_History.sql` migration;
`Prepare_WorkOrder_Edit_Checks.sql` supplies lookup indexes recommended for
large queues. See `ORDER_TOOLS_GUIDE.md` for use, deployment, and verification.
